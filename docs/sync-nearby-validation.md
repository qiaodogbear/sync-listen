## 双模拟器环境

- Emulator 36.6.11，API 35 Google APIs x86_64，Pixel 6 AVD SyncListen_A / SyncListen_B。
- 两机使用 WiFiPacketStream 与 AndroidWifi。分配地址 A=10.0.2.16、B=10.0.2.17，动态发现而非硬编码。
- A 启动手机内嵌 Host，B 直接通过共享虚拟 Wi-Fi 访问 A。附近交互和 B 加入不依赖 adb 端口转发。
- 电脑上的独立 QA 客户端通过 adb forward 访问 A，验证上传、鉴权和播放控制；它不是房间服务器。
- 测试昵称 AliceSync / BobSync / Lab，合成 45 秒 WAV，不含真实用户音频。
- WAV 共 1,440,044 字节，SHA-256：88afa2731e4221b9be840733ef0f50683f8aff8dddd04a2fe2bfd5bb85655628。
- 模拟器关闭音频输出，因此只验证播放器与协议状态，不能测听觉效果。
- 低内存冷启动期间出现过系统 UI / Telephony 服务 ANR；本轮 App crash buffer 未发现崩溃。此结果不能证明任意设备长时间无崩溃。

## 同步观测如何解读

B 的一次连接观测为 RTT 15ms、服务器 offset 174ms、不确定度估计 10ms；一次运行采样的软件位置误差为 12ms，速度 1.0x，检查点计数 251。它们只是不同采样时刻的诊断值，不是声学误差、双机同时测量、统计分布或性能上限，也不能证明“稳定 12ms”。

纯算法模拟覆盖初始 200ms 偏差和 200ppm 漂移，40 秒收敛到 40ms 容差内且无需 seek。实际网络不对称、解码耗时、系统调度、扬声器和蓝牙输出路径并未被该模拟建模。

本轮没有缩短服务器 1500ms 计划提前量。下一步降低控制等待需要成员 READY 屏障和自适应调度，见 [设计文档](sync-and-nearby.md)。

## 验收中发现并修复

1. 快速断开/重连可能使旧连接的延迟计划重新执行。增加连接代数，等待后再次确认；已有单测覆盖。
2. 断网时 UI 将历史误差继续标为“正常”。删除凭误差大小推断状态的文案，改显示最近采样、断线过期与实际纠偏策略；同时解释 UI 当前进度与检查点不是同时取样。
3. 结束房间后首页保留旧恢复卡片，重开进程后消失。确认数据库恢复标记已清理，问题来自页面初始化读取活动房间快照并留在内存。限制恢复检查时机、作废旧异步查询，并在结束时清空内存。新增真实 Room 内存数据库设备测试，不能用删除数据库伪造通过。

最后两项的最终构建与设备回归已完成。交付 APK 在 A 安装成功，进入房间、进入设置、迷你栏返回、诊断面板新文案、显式结束后立即无恢复卡片均已验证；离房后没有活动 App Service，crash buffer 为空。最终冷重开后的 UI 抓取曾返回 null root，未拿旧 XML 将该步计为通过。

双模拟器矩阵执行在最后两项显示/恢复状态修复之前；最后追加修改经过全量自动回归与上述单模拟器检查，没有重复整个双设备矩阵。

## 剩余验证边界

- T605 未完成：两台真机的声学输出偏差 p50/p95/最大值，普通路由器/热点隔离兼容性、IPv4 地址切换、长时锁屏、来电、蓝牙耳机和耗电。
- 本轮未重新执行真机 BLE、NFC、物理摄像头扫码，也未执行桌面音频输出的声学测试。
- 悬浮窗授权由 A 的系统设置 UI 操作；B 没有授权跨应用窗口，不能声称已检查 Member 的实际覆盖窗口。
- 附近功能仅 Android 前台且用户开启时运行，昵称未经身份认证，无法发现“附近但不在同一互通网络”的所有用户。
- 两个测试房间均显式结束；AVD 已关闭、定义保留，adb 转发移除，A 临时通知/悬浮窗授权还原，B 数据与 Wi-Fi 恢复开启。不修改用户真实手机的权限。
