# 已知问题与下一阶段优化

适用版本：v0.3.0 preview。这里列的是未完成项，不把历史计划或模拟器通过当作真机认证。

## 优先稳定性

| 优先级 | 限制 / 风险 | 下一步与验收条件 |
|---|---|---|
| P1 | 普通成员没有完整 MediaSession 前台播放服务；后台长时间播放可能被系统限制 | 独立播放服务、通知控制、音频焦点测试；至少三类真机锁屏 2 小时、来电/耳机断开回归 |
| P1 | 手机托管使用 dataSync 前台服务，Android 15 和厂商省电可能限制长时运行 | 核对服务类型与产品用途；实测系统超时、切后台与恢复，不靠无限重启规避限制 |
| P1 | 恢复位置来自最近持久化命令；强制停止前的连续播放进度不保证保存 | 增加限频检查点；故障注入验证写入失败与取消，恢复误差有明确上限 |
| P1 | 下载队列串行链内永久失败可能阻塞后续任务；已有工作排序不是实时抢占 | 每曲独立状态与可重建队列；失败曲目不阻塞其他歌曲，当前/下一首优先，磁盘满可恢复 |
| P1 | 没有服务器总存储配额、速率限制和完善自动清理调度 | 加配额和引用计数，验证并发上传/清理/播放保护、断电与磁盘满 |
| P1 | 三套服务端实现仍有维护重复，Android 尚未整体使用 shared | 增加同一套协议合同测试后逐步提取纯逻辑，保留平台持久化边界 |

## 易用性与界面

- 无真正的“所有成员已缓存再统一开始”门槛，慢设备可能晚加入播放。应增加成员就绪状态和房主等待提示。
- 下载失败提示和重试入口需统一；缓存清理与下载同时发生时仍需事务级保护。
- 托管网络切换后旧邀请地址可能失效。应主动检测、提示并生成新邀请，不能自动迁移已有房间凭据到任意地址。
- 诊断面板在小屏、放大字体时可能拥挤；应改为可滚动详情页，房间主界面保留关键信息。
- 完善桌面离房确认、键盘导航、可访问性语义和批量选择反馈。主题美化排在状态可靠与交互闭环之后。
- 当前 lint 为零错误但仍有警告，需按兼容性/无障碍/维护性分批清理，不能把 lint 通过当作零风险。

## 平台与网络边界

- Android 最低 API 26，目标 API 35。本轮 AVD 为 API 35，不代表所有最低版本和真机已经验收。
- Host 必须在线；不支持主机迁移。普通成员进程退出后需重新加入，Host 异常退出提供主动打开后的恢复入口。
- HTTP / WebSocket 明文传输，只有设备凭据和角色校验，没有账号、内置 TLS、邀请尝试限流或远程托管平台。
- 设备需处于互通的 Wi-Fi/热点网络；客户端隔离、VPN、防火墙和厂商热点策略都可能阻断连接。
- 二维码编码/解码及深链有测试；本轮没有物理双摄扫码、BLE 射频发现或 NFC 实物标签测试。
- Windows 本轮验证 PCM WAV。MP3 解码支持已集成但未作广泛兼容性认证，FLAC/WMA 等不作桌面支持承诺。
- Android 文件选择器接收多种音频 MIME，实际能否解码由容器、编码及设备决定，不支持受 DRM 保护的内容。
- 不提供逐采样同步；蓝牙、耳机、声卡和扬声器延迟不包含在软件同步误差中。
- Windows 分发包尚无 Authenticode 签名。Android 正式版使用独立签名，与过去 Debug/其他签名包的升级规则不同。
- 根目录 render.yaml 的旧 free plan + persistent disk 组合不能直接作为有效的免费部署方案；本轮未部署 Render/Fly，也未产生付费资源。需自行调整并验证。
- Node 的 node:sqlite 可能输出 ExperimentalWarning。Windows 中文路径单测推荐 ASCII subst 映射。
- 本轮未运行真实 SQLite Android 仪器化迁移测试；Room/KSP 与 Fake DAO 测试不能完全替代设备级数据库测试。
