# 全量分块审查与工程优化

日期：2026-09-16。目标版本：v0.3.0 preview。起点：feat/mvp / 1aeede3，包含当时未提交的 Android 和桌面界面工作，未回退这些改动。

## 结论与风险

本轮确认并修复了成员身份冒用、角色权限遗漏、共享目录过宽、托管写入一致性、桌面播放器生命周期与缓存缺失等问题。实际模拟运行还发现了曲终后 seek 未真正暂停、再次播放未从头开始以及诊断数据显示错误，已补修并纳入最终回归。

这不是“没有缺陷”的证明，也不是公网安全认证。当前仍有需要继续投入的领域：成员后台播放服务、真机长时间托管、队列永久失败恢复、存储配额、网络变更和设备音频延迟。以可信局域网预览版发布，不把它包装成生产级音频同步系统。

验证数字与最终运行结果以 [测试报告](test-report.md) 为准。待办统一维护于 [TASKS.md](../TASKS.md)。

## 审查方式与范围

- 全量文件清点：递归清点 android-app / backend / shared / desktop / protocol 的 Kotlin、TypeScript 源码与测试；排除 build、dist、缓存、node_modules。
- 总计 163 个文件：118 个生产文件，45 个测试/测试辅助文件；物理行数约 1.68 万，包含空行和测试，不是覆盖率。
- 按模块追踪请求、身份、文件流、锁/事务、生命周期、UI 状态和失败路径；对高风险代码逐段阅读，并使用全局静态搜索找吞异常、一次性播放器、未鉴权接口及占位回调。
- 运行既有测试建立基线，再新增协议、鉴权、范围下载、设置并发、缓存、播放与事务失败回归；使用模拟器运行正式签名产物。
- 工程配置、Manifest、资源、Gradle/npm、CI、部署文件、签名和仓库历史另行检查，不混入 Kotlin/TypeScript 文件计数。
- 未运行第三方专业渗透测试、全部 Android 仪器化测试或 JVM 依赖完整漏洞扫描；npm audit 仅说明当时 npm 数据库对 npm 依赖的结果。

可重复清点命令：

```powershell
node scripts/review-inventory.mjs
```

逐文件清单：[inventory.md](review/inventory.md)，机器数据：[inventory.json](review/inventory.json)。

## 确认问题与修复

按优先级列出。P1 表示可导致未授权访问、主要流程失效或数据不一致；P2 表示特定场景行为错误、兼容性或维护性问题。

| ID | 优先级 | 原问题与后果 | 本轮处理及关键证据 |
|---|---|---|---|
| R01 | P1 | 只靠 userId 和房间邀请，成员可冒用 Host；部分读写/下载/角色接口无独立身份验证 | backend/src/auth.ts、两侧 HostServer/HostRoomStore、新 DeviceAuthInterceptor；每设备按 origin 派生凭据；伪造身份/越权集成测试 |
| R02 | P1 | FileProvider 共享整个文件系统根，扩大文件暴露范围 | Android file_paths.xml 仅允许 shared-apk 子目录；APK 先复制到专用缓存再分享；关闭身份备份 |
| R03 | P1 | Android Host 多表写入和内存状态可部分成功，恢复后状态不一致 | HostServerService 使用 Room withTransaction；HostRoomStore.mutate 失败还原内存；父表从 REPLACE 改为 @Upsert，避免更新房间时级联删除歌曲；新增真实 Room 连续恢复测试及提交失败回归 |
| R04 | P1 | Desktop 准备即播放、队列空引用、释放后执行器不能复用 | DesktopPlayerEngine 改为每会话独立解码/输出/线程；load 只准备，play 显式开始；EOF、释放重用和暂停 seek 测试 |
| R05 | P1 | Desktop 缺少可靠自动下载与校验，播放器不能获得正确文件 | DesktopCacheResolver 流式下载、临时文件、长度/hash 校验与提交；AppState 在缓存就绪后重新同步 |
| R06 | P1 | 吞取消、旧房间事件/连接残留、托管启动与恢复竞态 | Repository/上传传播 CancellationException；WS 清理旧会话；服务启停串行化；恢复后真正重新加入原身份 |
| R07 | P2 | SQLite 重排直接交换唯一顺序产生冲突，遗漏/重复列表缺少校验 | 精确排列校验，事务内临时负序号再归位；保护当前曲目；回归无效排列与并发上传 |
| R08 | P2 | seek 把暂停变播放，提前 SYNC 抢跑；READY/ENDED 后 pause 可能未传到引擎 | 三端服务端保留 paused 状态；调度前不推进 SYNC；播放器无论 READY/ENDED 均能暂停，重复 Ready 保留 PAUSED；曲终重播归零 |
| R09 | P2 | 身份初始化并发会产生不同 ID；桌面设置写入可能丢更新 | 全局身份初始化锁、StateFlow.update、文件锁/原子移动；并发初始化与持久化/不同 origin 测试 |
| R10 | P2 | 文件大小信任元数据，缓存未充分校验；上传开始时多选检查尚未结束 | 限制实际读取字节、流式 hash、已有缓存重新核对；批量检查期间禁止开始/替换批次；取消关闭网络响应 |
| R11 | P2 | 端口/HTTPS BLE 邀请不可编码，NFC UTF-16 标志错误；深链入口处理重复 | 严格输入与能力检查、统一邀请确认、重复导航限制；BLE/NFC/二维码解析单元测试 |
| R12 | P2 | minSdk26 调用了 API30 clearCapabilities | 改为低版本可用能力移除 API，lint 回归；保留 LAN 不必被标记 Internet validated 的设计 |
| R13 | P2 | 诊断始终显示文件缺失/缓冲0，时间用了歧义冒号，小屏面板挤掉列表 | 实际路径与 Media3 bufferedPosition 上报、最终位置事件、明确“上次 SYNC”采样语义、限定高度滚动 |
| R14 | P2 | Release 回退 Debug 签名、跟踪大量 build 文件、云地址按钮不可用 | 独立外置签名、移除 415 个生成文件的索引跟踪但保留本地文件；CI；删除无效云入口；修正 Fly 数据挂载，说明 Render 旧配置限制 |

本轮未以大规模搬动目录代替问题修复。保留 Android / Desktop 的平台边界，仅提取 DeviceCredential 公共计算；后续通过合同测试逐步缩减三套服务端的重复逻辑。

## 后续优化门槛

先稳定，再易用，最后统一 UI 美学，与用户优先级保持一致。

1. 建立三类真机的长时播放矩阵，加入 MediaSession 播放前台服务、来电/耳机/电池策略与后台恢复验证。
2. 把下载与缓存变成可观察、可重试的单曲状态机；磁盘满、损坏文件和前一曲失败不阻塞其他歌曲。
3. 加成员就绪门槛和网络变更提示。邀请地址不可达、权限不足、文件不可解码都要给出清晰下一步。
4. 增加协议合同测试与 Android 真数据库迁移/故障注入测试，再逐步提取公共核心。
5. 清理剩余 lint 警告、统一页面结构与主题，补大字号、窄屏、TalkBack 和键盘操作。

## 发布边界

用户已批准公开现有仓库与采用 MIT。发布包使用独立 Android RSA4096 签名；私钥和 DPAPI 密码文件留在仓库外。Windows 包保留运行时及第三方许可证，另附对应第三方源码包。

公开前执行索引/历史的已知密钥格式扫描并检查待提交文件，不能把“没有匹配”理解为绝对没有秘密。测试音频、数据库、模拟器截图原始诊断、邀请 token 和签名材料不纳入 Git。

实际提交、发布链接、产物 SHA-256 与最终验收结果见 [发布说明](releases/v0.3.0.md) 和 [执行日志](../EXECUTION_LOG.md)。
