## 1. 项目概述

Sync Listen 是一个多人同步听歌应用，支持 **Android 手机**、**Windows 桌面** 和
**云端服务器** 三种运行模式。用户加入同一房间后共享播放列表，各设备下载并校验
MP3/FLAC/OGG/AAC/WAV/Opus/M4A/WMA 文件后本地播放。HOST 或 ADMIN 统一控制播放，
客户端通过服务器时钟、计划执行时间、周期 `SYNC`、seek 和变速修正实现同步。

### 部署方式

1. **云端模式**：部署到 Render/Fly.io，所有设备通过互联网连接（推荐日常使用）。
2. **电脑后端模式**：Windows 运行 Node.js/Fastify，手机/桌面通过局域网访问。
3. **手机托管模式**：一台 Android 手机运行内嵌 Ktor/CIO 服务，其他设备通过热点加入。
4. **桌面托管模式**：Windows 桌面版运行 Ktor 服务，支持更大存储和更快的上传下载。

## 4. 当前架构与权限模型

### 4.1 权限矩阵（阶段 D）

| 操作 | HOST | ADMIN | MEMBER |
|------|------|-------|--------|
| 创建房间 | ✅ | — | — |
| 播放/暂停/切歌/Seek | ✅ | ✅ | ❌ |
| 上传歌曲（单个/批量，最大 500MB） | ✅ | ✅ | ✅ |
| 删除播放列表中的歌曲 | ✅ | ✅ | ✅ |
| 拖拽调整播放顺序 | ✅ | ✅ | ✅ |
| 任命/撤销 ADMIN | ✅ | ❌ | ❌ |
| 踢出成员 | ✅ | ❌ | ❌ |
| 关闭房间 | ✅ | ❌ | ❌ |

### 4.2 新增 API 端点

| 端点 | 方法 | 说明 |
|------|------|------|
| `PUT /api/rooms/{id}/members/{userId}/role` | PUT | 任命/撤销 ADMIN |
| `PUT /api/rooms/{id}/playlist/reorder` | PUT | 批量调整顺序 |
| `DELETE /api/rooms/{id}/tracks/{trackId}` | DELETE | 移除歌曲 |

### 4.3 数据流

```
Compose UI → ViewModel → Retrofit REST + OkHttp WebSocket
→ RoomRepository → WorkManager 下载 → Room 缓存 → Media3 播放
→ PlaybackSyncManager → ServerClock → 同步修正

三种服务器后端实现相同 REST/WebSocket 协议：
  Fastify（云端/电脑） | Ktor CIO（手机 Host） | Ktor CIO（桌面 Host）
```

## 9. 已知问题与限制

- 当前是本地/可信网络原型：无账号、TLS、速率限制或持久会话认证。
- Host 离开会关闭房间，不支持 Host 迁移或多 Host。
- Node.js 24 的 `node:sqlite` 输出 ExperimentalWarning。
- NFC 仅通过 API 35 模拟器验收，真实 NFC Tag 待补验。
- 同步目标是"大致同步"，不是样本级同步。
- 桌面版 UI 为功能验证阶段，未完成完整房间界面。
- 拖拽排序和批量导入的 Android UI 尚未实现（API 已就绪）。
