## 产品与现状

Sync Listen 让同一局域网内的朋友共享本地歌曲和播放进度。Android 手机可内置 Ktor 托管，其他手机或 Windows 客户端加入，无需电脑后端。可选 Node/Fastify 后端也使用同一协议。

设备下载并校验相同文件后各自本地播放；不是实时音频流，也不是从商业音乐 App 抓取声音。手机托管不需要互联网，但必须有互通的 Wi-Fi 或热点，Host 必须在线。

当前实现：临时身份、邀请、Host/Admin/Member、上传下载/去重、缓存、本地播放、时钟/计划控制/纠偏、断线重连和 Android 托管恢复。当前桌面 UI 只作为客户端，shared 中的内存 Ktor 库不等于桌面已有托管入口。

## 如何模拟运行

两个 Pixel 6 AVD 已创建：SyncListen_A / SyncListen_B，API 35 Google APIs x86_64。启动一个，等 adb boot_completed=1 后安装 APK，完整 Activity 类名为 com.synclisten.app.MainActivity。

Debug applicationId 是 com.synclisten.app.debug，正式版是 com.synclisten.app。两者可以并存，但同一模拟器不要同时启动两个托管服务争抢 38571。

手机模式：A 用界面创建房间，adb 把 A 的 TCP38571 转发到宿主机，B 填 http://10.0.2.2:38571 和房间码。真机用房主可达局域网 IPv4，不用 adb 转发。

电脑模式：backend 内 npm run dev，模拟器填写 http://10.0.2.2:3000，真实手机填电脑 LAN 地址。端口监听、网络隔离、防火墙需分开诊断。

本轮验收用自行生成的 45 秒 PCM WAV，避免把私人音乐放进公共仓库。扫码编码/深链注入和真实摄像头扫码必须分开记录。

## 如何调试和复现

- 后端：lint、typecheck、Vitest、build；检查 /health。保护 API 必须带 X-User-Id / Authorization。
- Android：testDebugUnitTest、lintDebug、assembleDebug；adb logcat、dumpsys activity、uiautomator、screencap。
- 桌面：shared:test、desktop:test、createDistributable；假音频输出测试不能代替实际声卡测试。
- 同步：观察 serverOffsetMs、rttMs、上次 SYNC 误差与速度，不能把错时 UI 截图相减当作精确声学同步误差。
- 恢复：测试房间中暂停，再 force-stop Host、重开并用恢复卡片；核对房间码、曲目和暂停位置。显式结束后不应再有恢复卡片。
- 分享日志前去除设备密钥、Authorization、邀请 token、本地个人路径及私人音频。

## 继续优化什么

优先顺序不变：稳定、易用、最后统一界面美学。

1. 完整成员后台播放服务、MediaSession、系统通知与耳机/来电处理，真机锁屏和长时运行。
2. 下载队列按单曲可恢复、全局空间配额、并发缓存清理保护、损坏/失败/重试反馈。
3. 限频持久化播放检查点、真实 Room 迁移和断电测试、网络切换重新邀请。
4. 全体成员就绪后开始、可理解的错误与重试、桌面音频解码矩阵。
5. 共用合同测试约束三套服务端，渐进提取 DTO/校验/同步纯逻辑，不一次性重写平台 IO。
6. 大字号/小屏、TalkBack、桌面键盘操作、统一导航和状态组件，再做整体视觉整理。

P2 仅留 backlog：主机迁移、Mesh、无路由组网、实时音频流、iOS 与远程服务。不要把这些写成当前已有卖点。
